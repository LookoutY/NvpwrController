Nvpwr Power Console 3.0.6

[加载方式选用指南]

主页“加载方式”旁的问号按钮可打开本指南，驱动会话运行时也可查看。

为什么 EfiGuard 按钮是灰色？
正常启动会自动加载上次保存的后端，出现“驱动会话已就绪”后，KDU 和 EfiGuard 都会锁定。
这是避免同一会话中混用加载和 DSE 恢复方式的保护，并非已判定电脑不支持 EfiGuard。
先点主页“结束会话”，等待完成且没有 DSE 待恢复，再选择后端，最后点“加载驱动”。
若正在执行操作，先等待；若签名校验恢复失败，先恢复或重启 Windows，不要强制切换。
选择 EfiGuard 只保存选择，不会安装或激活 EFI 补丁；“可以选择”和“已经能加载”不是一回事。

KDU 和 EfiGuard 有什么区别？
KDU 在 Windows 启动后借助有合法签名但存在漏洞的驱动，临时改变内核 DSE，再正常加载 Nvpwr。
本工具在加载结束或失败后立即尝试恢复原始 DSE；KDU 路线不需要事先从 EFI 启动盘启动。
EfiGuard 在 Windows 启动前修补启动链和内存中的内核，涉及 PatchGuard 与运行时 EFI 钩子。
进入 Windows 后，本工具通过已经存在的 EFI 钩子临时调整 DSE，加载 Nvpwr，再恢复 DSE 原值。
因此 EfiGuard 需要额外的 EFI 启动准备；仅点本工具中的 EfiGuard 按钮不能补上这一步。
两种方式最终使用同一个 Nvpwr.sys / NvpwrCtl.exe，功耗范围与回读规则完全一样，都无需测试模式。
EfiGuard 并不天然更安全、功耗更高或保证兼容反作弊；两种方式均可能蓝屏或被安全软件检测。

什么情况下用哪种？
- KDU 当前能正常加载：先沿用 KDU，不必为了尝试新后端改启动链。
- KDU 加载受系统版本或驱动阻止策略影响：先看日志、兼容性和上游说明，不要连续强行重试。
  只有已经了解 EFI 启动、具备恢复条件并确认 EfiGuard 与当前 Windows 版本兼容，才考虑它作为替代。
- NVIDIA 驱动已经加载，只是功耗回读不符或出现 0x65 超时：更换加载方式不保证解决此类问题。
- 必须保持当前系统保护或反作弊要求、不接受启动链改动：不要使用 EfiGuard；不能满足条件时停止使用绕过加载路线。

KDU 使用
1. 正常启动本工具并授予管理员权限；选中 KDU 时会尝试自动准备驱动。
2. 若另一个后端已有会话，先“结束会话”，再选 KDU 并“加载驱动”。
3. 驱动就绪后选择功耗并应用。报错时看本次操作日志，不自动关闭系统安全策略。

EfiGuard 使用：必须先从 EFI 启动
1. 保存工作，准备 BitLocker 恢复密钥，确认可使用固件的一次性启动菜单和正常 Windows 启动项。
	核对当前 Windows 版本与随附 EfiGuard 的兼容性，不把上游泛称支持 Windows 11 当作本机已验证。
2. 在“运行依赖”点击“导出 EFI 文件”，选择空目录。程序仅导出两个文件：
	EFI/Boot/bootx64.efi
	EFI/Boot/EfiGuardDxe.efi
	将完整 EFI 目录复制到已准备好的 FAT32 U 盘根目录；不要覆盖系统盘上的 EFI 分区或现有引导。
3. 使用随附未纳入固件信任链的 EFI 文件时，Secure Boot 通常需要在固件中手动关闭；
	自行签名并建立可信链属于高级配置，本工具不会代办。若不接受降低保护，请不要继续。
	本工具还要求 HVCI 和 VBS 实际未运行；内存完整性关闭不一定意味着 VBS 已停用。
	在系统安全设置和 Windows“系统信息”中核对状态，按系统要求重启，不要删除代码完整性策略。
4. 通过固件的一次性启动菜单，选择该 U 盘的 UEFI 启动项，而不是 Legacy/CSM。
	成功时应看到 EfiGuard 的启动信息并随后进入 Windows；如有补丁失败或兼容性错误，停止尝试。
5. 进入 Windows 后打开 Nvpwr。如果 KDU 已自动加载，先点“结束会话”，再选 EfiGuard 并“加载驱动”。
	若上次已保存 EfiGuard，正常启动会尝试该后端；仍需实际 EFI 钩子检查通过才能加载。
6. 本工具先检查 EFI 钩子、读取 DSE 原值、临时关闭、加载 Nvpwr，然后恢复原值并读回验证。
	检查失败不等于只缺一个开关；查看日志，确认本次确实经过 EFI 启动，不要反复加载或关闭更多保护。
7. 驱动就绪后再应用功耗。“结束会话”不保证恢复原厂功耗，恢复 DSE 也不会撤销本次启动中的 EFI 补丁。

退出这条 EFI 路线
本指南使用临时 U 盘启动，不安装持久引导项。保存工作，完整重启，并通过原来的 Windows Boot Manager 启动，
不要再次选择 EfiGuard U 盘。之后按需要恢复 Secure Boot/内存完整性等设置，并核对状态。
仅关闭本工具、拔出 U 盘或改回 KDU，都不能撤销当前这一次 Windows 启动中的 EFI 补丁。
本工具不会替你重启、改写 EFI 系统分区或创建启动项。

[程序与状态说明]

唯一入口：release/Nvpwr.exe。原生 C# / WPF，无 BAT、PS1 或 PowerShell 启动链。
界面、说明和七个必要底层组件均内嵌在 EXE 中，复制该文件即可携带程序。
所有运行生成文件集中到 Nvpwr.exe 旁的 NvpwrData 文件夹，不散落在 EXE 同级，也不写 AppData。
底层 SYS/EXE/DLL、后端设置 backend.txt、启动日志 startup.log、说明 README.txt 都位于 NvpwrData 内。
会话日志放在 NvpwrData/logs 子目录，自测截图放在 NvpwrData/diagnostics/ui 子目录。
目录不可写时会明确报错，不会回退到其他位置。不会自动更改 D 盘根目录或创建外部备份。
环境：Windows 10 1809+ / Windows 11 x64，.NET Framework 4.8。

请从 release/Nvpwr.exe 启动；obj 内的 EXE 是编译中间文件，不是发布入口。
服务检测直接读取 Windows 服务管理器，不再把 WMI 漏报当作“服务不存在”。
已有的停止服务会复用并更新驱动路径；创建时遇到 1073 会重新查询，不删除服务。
状态未知、同名非驱动服务或其他位置正在运行的驱动会被明确阻止。

固定 940 x 550，灰蓝主题；主页切换 KDU / EfiGuard。
功耗说明、选择、手动输入、后台校验统一为 175-300 W，5 W 步进。
活动驱动会话或 DSE 待恢复时不能切换后端，须先结束会话。
正常启动请求管理员权限并尝试准备驱动，但不自动设置功耗。
勾选风险确认后，点击应用直接执行；输入错误、回读不符、重启及恢复失败等告警保留。
测试签名模式 / Test Mode 保留当前运行状态和启动配置，右侧新增“测试模式设置”。
点击后选择开启或关闭，经确认才提交；命令完成后会读取 BCD 验证，需要手动重启 Windows 生效。
不会自动重启、安装证书、卸载驱动，也不会修改 Secure Boot 或内存完整性。
开启要求 Secure Boot 关闭；无管理员权限、只读、操作进行中或 DSE 待恢复时禁止提交。
普通驱动会话不会锁定此入口。KDU / EfiGuard 本身无需开启测试模式。
更改前请准备 BitLocker 恢复密钥；测试模式可能影响系统保护及部分反作弊软件的兼容性。
Secure Boot 和内存完整性继续使用各自的系统设置入口。

日志按每次操作独立分组：序号、时间、动作、后端与结果。
右侧下拉框可选择不同操作，不混在同一个长文本里。
每次程序启动分别保存到 NvpwrData/logs/运行时间-标识/。
复制和导出针对当前选中的日志组。

本地 EfiDSEFix 的 -c 是检测，-r 是读取，-d 是关闭，-e 原值 才是恢复。
新版会检测、读取原值、临时关闭、加载、恢复并读回核对；不会把 -r 误当恢复。

175 W 若回读仍为 200 W，会提示不一致并阻止继续写入。
若完整 STOCK_BASELINE、OEM、实际功耗、F7、目标一致且增量为零，则显示已处于原厂功耗。
缺失或矛盾数据以及真实底层错误不会被该原厂状态例外掩盖。
Last NVIDIA status 为 0x65 表示 NV_ERR_TIMEOUT，即驱动调用超时，不等于不支持该功耗。
即使回读与目标一致，超时结果仍标记为未确认；提示中显示具体状态和耗时，不再只有 Exit: 6。
可稍候手动重试同一目标；持续出现则停止频繁调整。程序不会自动重复写入或重启显卡。
日志记录目标、回读、退出码、NVIDIA/NT 状态、调用耗时及结果分类，便于区分后续问题。
F7 是驱动策略而非实时耗电，175-300 W 也不是硬件安全额定范围。
内核修改可能蓝屏，功耗修改可能损坏硬件；卸载辅助驱动不等于恢复 OEM 策略。
不自动关闭保护、不删除代码完整性策略、不承诺反作弊兼容。

安全诊断参数：
Nvpwr.exe --preview          模拟界面，禁止系统写入
Nvpwr.exe --read-only        本机状态，只读
Nvpwr.exe --manual-load      管理员界面，不自动加载驱动
Nvpwr.exe --check            检查内嵌组件
Nvpwr.exe --self-test        原生隔离测试及界面自测
Nvpwr.exe --live-self-test   原生真实只读启动自测
诊断结果：NvpwrData/startup.log。
